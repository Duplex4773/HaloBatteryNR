# Dashboard audit — 4 October 2026

The dashboard now uses plain-language feedback, clearer grouping and native
scrolling. These changes keep the existing Rust/Win32 interface and on-demand
graphics, without introducing a UI framework or another runtime dependency.

## Findings and changes

| Finding | Change |
| --- | --- |
| Technical polling errors and unclear saved-rate state | Show Last confirmed rate separately from Saved choice; explain recovery steps and uncertainty in plain language. Exact errors remain in locally saved support reports. |
| Dense Settings page and controls below the window | Group common settings and put device brands and less-used options under More options. Keep Save settings and feedback in a fixed footer. |
| Unclear selected page | Highlight the selected navigation button in both light and dark appearance. |
| Small-window and keyboard access | Scroll Devices, Settings and Insights; keep navigation visible and focused controls in view. Clamp initial window height to the monitor work area. |
| Form edits lost during refresh or invalid input | Preserve same-device edits during inventory rebuilds and retain invalid values so the user can correct them. Unrelated device updates no longer rebuild Settings. |
| Hard-to-read battery predictions and dates | Lead Insights with estimated full-battery use and time left, explain learning progress, and use local dates. Label recorded sessions Use between charges. |
| Retained battery readings could look current | Label sleeping or stale retained levels last known and missing levels battery level unavailable. |
| Off-screen controls did not move reliably | Batch native child-window positions during scrolling, including clipped controls. Use the same viewport size for scroll limits and avoid fractional-DPI offset drift. |
| Focus lost during a page rebuild | Restore focus after redraw is enabled, when the native parent is visible again. |
| Loaded dashboard data could survive closing | Release Insights data on close alongside history, chart resources, fonts, theme brushes and native controls. |

Polling allowlists, packet formats, device identities, guarded one-time changes
and battery storage behavior are unchanged by the UI refinement. Polling errors
that may follow an applied change still instruct the user to Refresh rate; they
are never automatically retried. Saving a support report writes a local file and
does not transmit data.

## Resource accounting

The dashboard adds a native scrolling page host and a reused heading font while
open. Body and heading fonts are reused at the same DPI. Scrolling uses transient
native positions rather than a retained bitmap; History still streams chart
vertices. There are no new background timers, hardware queries on hover, workers,
webviews or graphics buffers retained after closing the dashboard.
